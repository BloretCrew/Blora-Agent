BLORA AGENT · ROADMAP

实施路线图。

从零实现的本地优先 Code / Work / Agent 工程代理：以规范事件为唯一事实来源， TUI 与 Web 双入口，能力策略默认拒绝，Bloret PassPort 设备码登录。本文记录全部阶段、 范围、验收标准、对应提交，以及明确的边界与后续候选。

01设计约束

这些约束贯穿所有阶段，任何阶段都不允许为进度破例。

事件是唯一事实

会话、审批、任务、记忆全部落在 SQLite 追加事件日志；未知事件类型不得破坏回放。

类型层零 IO

blora-types 不出现 IO 与供应商类型；供应商与执行细节只存在于各自的 crate。

克制运行时

优先新增 crate，而不是把 blora-runtime 养成单体；每个 crate 单一职责。

策略默认拒绝

工具能力 allow / deny / ask 三态，fail-closed；网络默认关闭，机密路径与破坏性 git 操作走审批。

Web 只用官方包

界面组件仅来自已发布的 @bloret-crew/blora-design；不引入第二套视觉体系，不 innerHTML 用户内容。

不 fork、不抄

GPL-3.0-or-later 从零实现；其他 harness 仓库只作研究参照，代码与结构不进入产品树。

05安全模型

凭据生命周期

  • Gateway 令牌 blt_… 明文只在创建时返回一次，库存 SHA-256
  • 设备码流程：access_token 与 device_code 留在服务端，浏览器只见 user_code
  • Web 会话为 HttpOnly + SameSite=Lax Cookie，Passport 侧凭据可随时换环境变量轮换

执行边界

  • 策略三态 fail-closed，未知工具一律 Ask
  • 路径逃逸（../）在执行层归一化后校验
  • 远程执行走 SSH 单通道，容器与沙箱一律断网
已声明的边界（诚实条款）：PTY 经 script(1) 而非原生 libc；远程是 SSH 而非 k8s 编排； 市场是本地索引而非签名公共商店；记忆是抽取式蒸馏而非训练；Gateway 是单进程多令牌而非分布式集群。
